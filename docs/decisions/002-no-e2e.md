# ADR-002: No browser E2E tests

Status: accepted

Context: v5 shipped without E2E tests. v6 adds `make docs`, which builds the frontend and drives it with headless Playwright to produce deterministic screenshots per route and mock-data state — overlapping heavily with what an E2E suite would need.

Decision: Skip a browser E2E suite; the `make docs` route-catalog fixtures (per-route, per-state mock RPC data + screenshots) are the integration surface.

Consequences:
- Playwright is a dependency of `make docs` only; there are no `.spec.ts` assertions.
- A route or state without a fixture fails `make docs`, catching most "forgot to wire it up" bugs without a live backend/DB.
- Cross-layer flows (OTP login, logout) rely on unit tests plus manual verification, not automated browser assertions.

Rejected alternatives:
- Playwright E2E against a live backend/DB: real coverage, but slow and flaky in CI for a small template.
- No integration surface at all: leaves UI regressions undetected between unit tests and manual QA.
